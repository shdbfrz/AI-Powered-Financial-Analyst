# MVP Definition — AI-Powered Financial Analyst

**Purpose of this document:** Define the smallest slice of the full vision
(`PDR.md`) that proves the end-to-end concept works — data in, prediction +
sentiment out, decision generated, explained in plain language, shown on a
dashboard — before layering in every optional model and feature. This is what
the team builds and demos first.

---

## 1. MVP Goal

Prove the full pipeline for **one ticker at a time**, with **one model per
model family**, end-to-end:

```
Yahoo Finance data → indicators → (1 ML model + 1 DL model) → prediction
   → news sentiment (FinBERT) → decision (signal + confidence + risk)
   → LLM explanation → dashboard showing chart + decision card + chat
```

If this works reliably for one ticker, every subsequent addition (more models,
more providers, portfolio view, more report types) is additive, not a redesign.

---

## 2. MVP Feature Set (in scope for v0.1)

### 2.1 Data & Modeling
- [ ] Data collection: Yahoo Finance only (`yfinance`), daily OHLCV.
- [ ] Feature engineering: MA, EMA, RSI, MACD (skip the rest for MVP).
- [ ] One ML model: **Random Forest** (skip Linear Regression / XGBoost for MVP).
- [ ] One Deep Learning model: **LSTM** (skip GRU/Transformer for MVP).
- [ ] Skip time-series (ARIMA/Prophet) for MVP — add in v0.2.
- [ ] Simple ensembling: average of ML + DL prediction with a naive confidence
      interval (no complex weighting yet).

### 2.2 Sentiment
- [ ] News collection: one free news API, last 7 days for the selected ticker.
- [ ] FinBERT sentiment scoring (positive/negative/neutral + score).
- [ ] Skip news summarization and classification for MVP.

### 2.3 Decision Support Engine
- [ ] Combine prediction + sentiment into: `signal` (Buy/Hold/Sell),
      `confidence_score`, `risk_score` (simple volatility-based), and a
      mandatory `educational_disclaimer` field.
- [ ] Skip portfolio-level suggestions for MVP (single-ticker only).

### 2.4 LLM Layer
- [ ] One LLM provider wired up (Groq recommended — fast, generous free tier).
- [ ] One capability only: **explain the decision object** in plain language.
- [ ] Skip: report generation, indicator explanations, multi-turn chat memory —
      add a basic single-turn chat Q&A if time allows, otherwise v0.2.

### 2.5 Backend
- [ ] JWT auth: register/login only (no password reset, no roles/permissions yet).
- [ ] Endpoints: `POST /auth/register`, `POST /auth/login`,
      `GET /analysis/{ticker}` (runs the full pipeline and returns the decision
      + explanation).
- [ ] PostgreSQL: `User` and `Prediction` tables only.

### 2.6 Frontend
- [ ] Login/register pages.
- [ ] Single page: ticker search box → price chart (Recharts) → decision card
      (signal, confidence, risk, disclaimer) → LLM explanation text block.
- [ ] Skip: portfolio dashboard, report export, historical prediction browsing.

### 2.7 Infra
- [ ] Docker Compose running locally (Postgres + backend + frontend).
- [ ] Basic CI: backend + ai tests must pass on PR.
- [ ] Skip production deployment (Nginx, cloud hosting) until MVP is validated.

## 4. MVP Success Criteria

The MVP is considered done when a teammate or the professor can:

1. Register/login on the deployed-locally dashboard.
2. Type a ticker (e.g. `AAPL`) and get, within a reasonable wait time, a price
   chart, a Buy/Hold/Sell signal with confidence and risk scores, and a
   plain-English explanation of *why* — generated by the LLM from the decision
   object, not fabricated independently.
3. See the educational disclaimer on every prediction shown.
4. Confirm via `pytest` (backend + ai) that the pipeline is covered by
   automated tests, and CI is green on the `develop` branch.

---

## 5. Why This Slice

- **One model per family** is enough to prove the ensemble + decision engine
  logic works; adding more models later is a matter of registering them with
  the same interface, not re-architecting.
- **One ticker, no portfolio** removes multi-entity complexity from the first
  milestone so the team can focus on getting the pipeline correct end-to-end.
- **LLM does one job (explain the decision)** — this is the riskiest and most
  novel part of the system (Module 8's "explains, never predicts" rule), so
  proving it works early de-risks the rest of the timeline.
